# Решения по проекту

Сюда записываем решения, которые не очевидны из кода: что выбрали и почему.

## 14.11.2026 — как отличаем предметы стандартного режима (задача 0.4)

**Решение:** предмет попадает в `data/static/items.json`, если выполняются три условия:
он продаётся в магазине (`shopable`), не отключён (`disabled`) и его реально покупали
в обычных матчах за последние 30 дней (есть в ответе `/v1/analytics/item-stats`).

**Почему:** в данных игры нет поля «предмет только для другого режима». По первым двум
условиям проходит 173 предмета, но 17 из них (тир 5, цена-заглушка 9999) в обычных матчах
не покупал никто. Условие «реально покупают» отсеивает их без списка исключений,
зашитого в код, — после патча всё пересчитается само.

**Цена решения:** совсем новый предмет появится у нас только после первых матчей с ним
(обычно в тот же день).

## 15.11.2026 — готовый билд на матч вместо формы с душами (задача 1.5а)

**Решение (автор проекта, уточнено в обсуждении):** один режим. На экране загрузки
игрок выбирает героя, врагов (отдельно — врага на своей линии) и, по желанию, тиммейтов;
сайт сразу выдаёт весь билд по порядку покупки с причинами и условными заменами.
Ввод душ убран совсем. Отметка «купил» — только закладка, без пересчёта.

**Почему:** в телефон смотрят только во время смерти, вводить что-то в это время некогда.
Порядок покупок от количества душ не зависит, а без live-данных у сайта нет новой
информации посреди матча — пересчитывать нечего.

**Что добавили к идее автора:** условные замены («если враг разогнался — …»), потому что
линейный билд не учитывает ход матча; и подписываем, что учёт тиммейтов — наша оценка,
а не статистика (в API нет статистики предметов в зависимости от союзников).

**Чем отличаемся от билдов в самой игре:** подстройка под конкретный матч и объяснение «почему».

## 15.11.2026 — ценность сайта: подстройка под конкретный матч

**Решение (автор проекта):** готовые билды уже есть в самой игре, а купленное игрок видит
в магазине. Поэтому ценность сайта — подстройка билда под состав матча: враги, линия
(пара на пару), тиммейты и предметы, которые у них скорее всего будут.

**Что проверено в API (реальными запросами):**
- линии — пара на пару, статистика «пара против пары» есть (`lane-matchup-stats`);
- «предметы против конкретного врага», в том числе только на линии, — есть;
- «предметы в зависимости от союзника» — нет; только через сырые данные (задача 1.5г);
- какие предметы обычно покупает каждый герой и когда — уже собираем (`data/stats/heroes/`).

**Порядок:** 1.5а (билд на матч) → 1.5б (линия) → 1.5в (прогноз предметов) → 1.5г (исследование) → 1.7.

## 14.11.2026 — как устроена оценка предмета (задача 1.3)

Оценка считается в процентных пунктах винрейта (п.п.) и складывается из трёх частей:

1. **Насколько с предметом побеждают чаще на этом этапе игры.** Этап определяем не по времени,
   а по богатству игрока: души на руках плюс стоимость купленных предметов, шагом по 3000.
   Винрейт предмета сравниваем с обычным винрейтом всех покупок на том же уровне богатства —
   это и есть «равные с равными». Время матча сайт не знает, а души игрок вводит сам,
   поэтому взяли группировку API `net_worth_by_3000`, а не `game_time_min`.
2. **Насколько предмет популярен на этом этапе:** +1 п.п. за каждые 10% игр, в которых его
   покупают на этом уровне богатства.
3. **Бонус за контру:** +1,5 п.п. за каждого врага, против которого предмет помогает
   (по ручному справочнику); за «неудобного» врага (наш винрейт против него ниже обычного) —
   +2,25. Не больше +4,5.

**Почему нужна популярность.** Первая версия считала только пункт 1 и на настоящих данных
советовала редкие предметы (их берут в 1–2% игр) вместо основы билда. У редких предметов
винрейт завышен: их покупают опытные игроки и в удачных играх. У основы билда прибавка
почти нулевая просто потому, что её берут все.

**Поправка на маленькую выборку.** К статистике предмета мысленно добавляем 300 «обычных»
матчей. Предмет с 5 победами из 5 после этого выглядит как обычный, а не как 100% побед.

**Ранги.** Статистика по богатству есть только для всех рангов сразу. Группа рангов
добавляет поправку: насколько предмет в этой группе лучше или хуже, чем в среднем.
Если у героя в группе меньше 2000 матчей — берём все ранги и пишем об этом.

**Бюджет.** Сначала идут предметы, на которые хватает душ. Остальные получают штраф
0,5 п.п. за каждую недостающую 1000 душ — так «на что копить» выбирается из близких покупок.
Улучшение стоит дешевле на цену уже купленного компонента. Предмет и его улучшение
одновременно не советуем.

Все числа лежат в одном месте — `SETTINGS` в `src/logic/recommend.js`. Их надо будет
подкрутить после отзывов игроков (задача 1.9).

## 14.11.2026 — группы рангов (задача 1.1)

**Решение:** низкие — Послушник…Аколит (бейджи 11–36), средние — Страж…Ритуалист (41–66),
высокие — Эмиссар…Этернус (71–116).

**Почему:** по распределению матчей текущего патча это примерно 33% / 38% / 29% —
группы получаются близкими по размеру. Ранг есть только у части матчей (примерно у 17%),
поэтому «все ранги» всегда содержит намного больше данных, чем любая группа.

## 14.11.2026 — один адрес API (задача 0.3)

**Решение:** все данные берём с `api.deadlock-api.com` (справочники — в разделе `/v1/assets`).

**Почему:** адрес `assets.deadlock-api.com` с рабочего компьютера не открывается
(ошибка TLS-соединения), а те же данные есть на основном адресе.
