# Deadlock Build Advisor — контекст проекта для Claude

## Что за проект
Русскоязычный сайт-советник для игры Deadlock (Valve). Игрок выбирает своего героя,
героев врагов, вводит души и купленные предметы — сайт за секунду показывает
следующие 3 предмета к покупке с объяснением «почему», контр-предметы, полный путь
билда и порядок прокачки. Сначала бесплатный сайт с рекламой (РСЯ), потом подписка,
Telegram-бот и, возможно, оверлей. Подробный план — в `PLAN.md`, бизнес-план — в
документе «План: сервис подбора билдов для Deadlock».

## Кто я и как со мной работать
- Я новичок: почти не умею программировать, делаю проект через вайб-кодинг. Работаю на Windows (PowerShell).
- Работаем строго по `PLAN.md`: **одна задача за раз**. Я пишу, например: «Делаем задачу 1.3».
- Перед тем как писать код — коротко (3–5 пунктов) скажи, что собираешься сделать.
- После изменений обязательно:
  1. покажи изменённый фрагмент кода;
  2. объясни простым русским языком, что он делает (каждый новый термин — одной фразой);
  3. скажи, как мне проверить, что всё работает (какую команду запустить / что открыть);
  4. предложи текст коммита и сделай коммит, если я согласен.
- Не делай больше, чем просит задача. Идеи «на потом» — допиши в раздел «Идеи» в конце `PLAN.md`.
- Если решение дорогое, необратимое или требует денег/аккаунтов — сначала спроси меня.
- Когда задача готова — отметь её `[x]` в `PLAN.md`.

## Стек и правила кода
- Только JavaScript (без TypeScript). Node.js 22 LTS.
- Сайт до этапа 3 — обычные HTML + CSS + JS-модули, без сборщиков и фреймворков.
  Должен открываться с GitHub Pages как статический сайт.
- Тесты — встроенный `node:test` (`node --test`).
- Минимум зависимостей: новую библиотеку добавляй только с объяснением, зачем она.
- Весь текст интерфейса — на русском. Комментарии в коде — на русском, короткие.
- Не хардкодить мету, число героев или предметов: всё берётся из данных.
- Логика рекомендаций — чистые функции в `src/logic/` (без DOM и сети), покрытые тестами.

## Данные
- Статистика: Deadlock API — `https://api.deadlock-api.com` (документация: `/docs`).
- Герои, предметы, цены, иконки: Static Assets API — `https://assets.deadlock-api.com` (документация: `/docs`).
- Лимиты (могут меняться): около 200 запросов/мин с одного IP, около 400/мин с ключом.
  Скрипты сбора делают паузу между запросами и повторяют при ответе 429/503.
- **Сайт никогда не обращается к API из браузера посетителя.** Данные собираются скриптом
  раз в сутки и лежат готовыми JSON-файлами в `data/`.
- Статистику разных патчей не смешиваем. В каждом файле — дата сбора и дата патча.
- API-ключ хранить только в `.env` (локально) и в GitHub Secrets. `.env` — в `.gitignore`.

## Правила по Valve и честности
- Только открытые данные. Никакого чтения памяти игры, инъекций и автоматизации внутри клиента.
- Не называть сайт официальным, не использовать логотип Valve/Deadlock как свой.
- В подвале сайта: «Не связан с Valve. Данные: deadlock-api.com».
- Если данных мало — честно показывать «мало данных», а не выдумывать.

## Структура папок
```
/                      корень репозитория
├─ CLAUDE.md           этот файл
├─ PLAN.md             план по этапам
├─ package.json
├─ .env.example        пример переменных окружения (без настоящих ключей)
├─ scripts/            скрипты сбора и подготовки данных (запускаются Node.js)
├─ src/
│  ├─ logic/           логика рекомендаций (чистые функции + тесты)
│  └─ lib/             общие помощники (запросы с паузами, чтение/запись JSON)
├─ data/
│  ├─ static/          герои, предметы, способности (из Assets API)
│  ├─ stats/           статистика текущего патча (из Deadlock API)
│  └─ manual/          ручные справочники: теги героев, контр-предметы
├─ site/               сам сайт (то, что публикуется на GitHub Pages)
│  ├─ index.html
│  ├─ css/  js/  icons/
│  └─ data/            копия нужных JSON для сайта (кладёт скрипт сборки)
├─ tests/              тесты
└─ docs/               заметки: api-notes.md, решения
```

## Команды
- `npm run fetch:static` — скачать героев и предметы
- `npm run fetch:stats` — скачать статистику текущего патча
- `npm run build:site` — подготовить данные и страницы в `site/`
- `npm test` — запустить тесты
- `npm run dev` — локальный сервер для просмотра сайта
