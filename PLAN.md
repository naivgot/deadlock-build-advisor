# План разработки: Deadlock Build Advisor

Как пользоваться этим файлом:
1. Положи `PLAN.md` и `CLAUDE.md` в пустую папку проекта и открой её в Claude Code.
2. Первое сообщение: «Прочитай CLAUDE.md и PLAN.md. Делаем задачу 0.1».
3. Делай задачи **по порядку**, по одной. После каждой — проверка по пункту «Готово, когда» и коммит.
4. Если задача не получилась за 2–3 попытки — попроси Claude объяснить, что мешает,
   и разбить задачу на части поменьше.

Обозначения: `[ ]` — не сделано, `[x]` — сделано.
«Запрос» — что можно дословно написать Claude Code.

### [x] 1.5а Билд на матч вместо формы с душами (решено с автором 15.11.2026)
- Проблема: игра динамичная, в телефон смотрят только во время смерти (10–30 секунд).
  Вводить души бесполезно: порядок покупок от них не зависит, а число устаревает за секунды.
  Без live-данных у сайта нет новой информации посреди матча — значит, и пересчитывать нечего.
- **Один режим. На экране загрузки:** мой герой, напарник по линии, два врага на линии,
  остальные враги и тиммейты (необязательно). Кнопка «Собрать билд».
- Ценность сайта — подстройка под матч (решено с автором): линия (1.5б), прогноз предметов
  врагов и тиммейтов (1.5в), влияние тиммейтов (1.5г). Купленное игрок смотрит в магазине игры —
  отметки на сайте необязательны.
- **Результат — готовый билд на матч по порядку покупки** (15–20 предметов по этапам)
  с причиной у каждого и порядком прокачки.
  - Ранние предметы — с учётом врага на линии (статистика API «против героя X на той же линии»).
  - Дальше — с учётом всех врагов (статистика + справочник контр).
  - Тиммейты — только простое правило «у команды уже есть контра» (статистики нет, подписать как оценку).
  - 2–4 условные замены: «если <враг> разогнался — вместо X возьми Y», «если отстаёшь — …».
  - Раздел «Ситуативные» — предметы под конкретные угрозы матча, с причиной.
  - Раздел «Тоже подходит» — предметы на границе: почти не уступают основным, можно взять
    по вкусу или вместо основного. Детали (сколько, как отбирать) — обсудить с автором.
- Тап по строке только зачёркивает её — закладка «где я в списке», без пересчёта.
  Кнопка «Новый матч» снимает отметки.
- Ввод душ, ранга и выбор купленного из всего списка — убрать с главной.
  Ранг — перенести в настройки (влияет на статистику, но вводится один раз).
- Данные: в `fetch-stats` добавить `item-stats` с `bucket=enemy_hero` (и вариант на той же линии),
  оставить топ предметов против каждого героя, чтобы файлы сайта не разрослись.
- **Готово, когда:** от открытия до билда на экране загрузки — меньше 20 секунд;
  после смерти найти следующий предмет — 0 тапов; тесты на порядок билда и условные замены.

### [x] 1.5б Анализ линии (2 на 2)
- Линии в Deadlock — пара на пару. Вход: мой напарник по линии и два врага на линии.
- Данные (проверено 15.11.2026):
  - `lane-matchup-stats` — «наша пара против их пары»: победы и разница в душах на 15-й минуте.
    Конкретная четвёрка редкая (~250 матчей), поэтому запасной вариант — пары и одиночные герои.
  - `item-stats` с `enemy_hero_ids=<враг>` и `same_lane_filter=true` — что покупают и с чем
    выигрывают против этого героя именно на линии. **Не используем:** один запрос на пару героев
    (1892 запроса по ~15 с), а все враги разом падают по таймауту. Вместо этого — справочник контр,
    враги на линии весят в 1,5 раза больше, на тяжёлой линии — ещё в 1,5.
- Выход: «Линия тяжёлая/ровная/лёгкая» + ранние предметы под врагов на линии
  с причиной («против Абрамса на линии чаще выигрывают с …»).
- **Готово, когда:** ранние предметы меняются в зависимости от врагов на линии; при малой выборке —
  честное «мало данных по этой линии», откат на одиночных героев.

### [x] 1.5в Предсказание предметов врагов и тиммейтов
- Идея автора: учитывать, какие предметы **скорее всего будут** у врагов и союзников.
- Реализуемо уже сейчас: у нас есть статистика покупок каждого героя по этапам
  («Пелена к 20-й минуте в 64% игр берёт кражу здоровья пулями»).
- Нужна разметка предметов по эффектам: кража здоровья, лечение, защита от пуль/спирита,
  снятие эффектов, иммунитет к контролю и т.п. Делать **автоматически** из характеристик
  предметов в API (`properties`), вручную — только проверка.
- Как влияет на билд:
  - враги массово берут кражу здоровья → выше ценность среза лечения;
  - враги берут защиту от спирита → спиритические предметы теряют ценность, пушечные растут;
  - враги берут иммунитет к контролю → ниже ценность предметов на оглушение;
  - тиммейт скорее всего возьмёт срез лечения/ауру → тебе это менее срочно.
- В причине честно писать, что это прогноз: «Пелена обычно берёт кражу здоровья (64% игр)».
- **Готово, когда:** у каждого предмета есть автоматические теги эффектов; тесты на 3+ сценария,
  где прогноз меняет порядок билда.

## Этап 5. Рост (по спросу)
- [ ] 5.1 Английская версия сайта и бота.
- [ ] 5.2 Оверлей для Windows (Tauri или Electron) — только если пользователи просят.
- [ ] 5.3 Live-данные матча: сайт сам знает героев, души и покупки — без ввода.
  Что выяснено 15.11.2026 (подробно — `docs/api-notes.md`, раздел «Live»):
  - **Состав матча** (кто за кого играет) отдаёт `/v1/matches/active`, но только для
    200 самых просматриваемых матчей. Обычный матч новичка туда почти никогда не попадает.
  - **Души и покупки в реальном времени** можно получить через трансляцию матча
    (`/v1/matches/{match_id}/live/url` + live-запросы). Без ключа — 6 матчей в час на IP,
    с ключом — 50 в час. Это хватит для теста, но не для сайта с сотнями игроков:
    нужно договариваться с командой API (задача 2.7) или свой сервер.
  - **Не выяснено:** как узнать `match_id` текущего матча игрока, если матч не в топ-200.
    Без этого автоматика не работает.
  - Трансляция идёт с задержкой, поэтому советы будут запаздывать.
  - Что разрешено правилами Valve: только открытые данные (трансляция для зрителей).
    Чтение памяти игры и любые программы внутри клиента — нельзя.

  скачивать их при сборке, как данные.
