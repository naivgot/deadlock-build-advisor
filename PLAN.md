# План разработки: Deadlock Build Advisor

Как пользоваться этим файлом:
1. Положи `PLAN.md` и `CLAUDE.md` в пустую папку проекта и открой её в Claude Code.
2. Первое сообщение: «Прочитай CLAUDE.md и PLAN.md. Делаем задачу 0.1».
3. Делай задачи **по порядку**, по одной. После каждой — проверка по пункту «Готово, когда» и коммит.
4. Если задача не получилась за 2–3 попытки — попроси Claude объяснить, что мешает,
   и разбить задачу на части поменьше.

Обозначения: `[ ]` — не сделано, `[x]` — сделано.
«Запрос» — что можно дословно написать Claude Code.

## Этап 0. Подготовка (1–2 дня, бесплатно)

Цель: рабочий репозиторий, понятные источники данных, справочник героев и предметов.

### [x] 0.1 Установить инструменты
- Установить Node.js 22 LTS и Git для Windows, создать аккаунт GitHub (если нет).
- Проверить в PowerShell: `node -v`, `npm -v`, `git --version`.
- **Готово, когда:** все три команды печатают версии.
- **Запрос:** «Проверь, установлены ли Node.js и Git, и если нет — объясни по шагам, как поставить их на Windows».

### [x] 0.2 Создать проект
- `git init`, `package.json` (type: module), `.gitignore` (node_modules, .env), `.env.example`,
  папки из структуры в `CLAUDE.md`, пустой `README.md`.
- Скрипты в `package.json` из раздела «Команды» (пока могут быть заглушками).
- Создать приватный репозиторий на GitHub и запушить.
- **Готово, когда:** репозиторий на GitHub, структура папок совпадает с `CLAUDE.md`.
- **Запрос:** «Сделай задачу 0.2: создай структуру проекта по CLAUDE.md и помоги запушить на GitHub».

### [x] 0.3 Разобраться с API и записать заметки
- Открыть документацию `https://api.deadlock-api.com/docs` и `https://assets.deadlock-api.com/docs`.
- Найти и записать в `docs/api-notes.md`:
  - как получить список героев, предметов и способностей (есть ли русская локализация — параметр языка);
  - endpoint статистики предметов (item stats): какие фильтры есть — герой, ранг, патч/даты,
    **есть ли группировка по времени покупки** (это нужно для слоя 2 логики);
  - endpoint статистики героев и матчапов (кто против кого);
  - endpoint порядка прокачки способностей;
  - endpoint популярных билдов;
  - как узнать дату/номер текущего патча;
  - лимиты, как получить бесплатный API-ключ, формат ошибок.
- Для каждого endpoint — один реальный пример запроса и кусок ответа.
- **Готово, когда:** `docs/api-notes.md` содержит рабочие примеры всех пунктов выше.
- **Запрос:** «Сделай задачу 0.3. Сделай по одному реальному запросу к каждому endpoint и запиши примеры в docs/api-notes.md».

### [x] 0.4 Скачать героев и предметы
- `scripts/fetch-static.js`: скачивает героев, предметы, способности; оставляет только нужные поля
  (id, имя, имя на русском если есть, тип предмета weapon/spirit/vitality, тир, цена,
  компоненты/апгрейды, иконка, короткое описание) → `data/static/heroes.json`, `items.json`, `abilities.json`.
- Только предметы стандартного режима, без отключённых/удалённых.
- Общий помощник `src/lib/http.js`: запрос с паузой, 3 повтора при 429/503, понятная ошибка.
- **Готово, когда:** `npm run fetch:static` создаёт три файла; число героев и предметов совпадает
  с тем, что видно в игре/на deadlock.wiki.
- **Запрос:** «Сделай задачу 0.4».

## Этап 1. MVP-сайт (1–2 недели, бесплатно)

Цель: работающий советник на GitHub Pages, данные обновляются сами раз в сутки.

### [ ] 1.1 Скачать статистику текущего патча
- `scripts/fetch-stats.js`: для каждого героя — статистика предметов текущего патча
  (MVP: все ранги вместе + 3 группы рангов: низкие / средние / высокие).
  Плюс матчапы героев и порядок прокачки.
- Пауза между запросами (не больше ~1 запроса в секунду), прогресс в консоли.
- Сохранять в `data/stats/` + `data/stats/meta.json` (дата сбора, дата патча, число матчей).
- **Готово, когда:** `npm run fetch:stats` проходит без ошибок, повторный запуск не ломает данные.
- **Запрос:** «Сделай задачу 1.1, используй endpoints из docs/api-notes.md».

### [ ] 1.2 Ручной справочник контр
- `data/manual/hero-tags.json`: для каждого героя теги — `heal`, `spirit-burst`, `gun-dps`,
  `cc` (контроль), `mobility`, `tank`, `summons` и т.п.
- `data/manual/counter-items.json`: для каждого тега — предметы-контры и одна фраза «почему».
- Claude делает черновик по описаниям способностей и предметов, **я проверяю** (или прошу знакомых игроков).
- **Готово, когда:** у каждого героя есть хотя бы 1 тег; у каждого тега — хотя бы 1 предмет;
  тест проверяет, что все id героев и предметов существуют в `data/static`.
- **Запрос:** «Сделай задачу 1.2: подготовь черновик справочника и список мест, где ты не уверен».

### [ ] 1.3 Логика рекомендаций (сердце проекта)
- `src/logic/recommend.js` — чистая функция:
  `recommend({ hero, enemies, souls, ownedItems, rankGroup }, data) → { next: [3 предмета], counters, buildPath, abilityOrder, confidence }`.
- Слои оценки (подробно — в бизнес-плане, раздел «Логика рекомендаций»):
  1. База: винрейт предмета на герое в патче и ранге, с поправкой на маленькую выборку.
  2. Время покупки: если API отдаёт группировку по времени — сравниваем «равных с равными»;
     если нет — пока пропускаем слой и пишем это в `docs/decisions.md`.
  3. Враги: матчап-статистика + справочник контр из 1.2.
  4. Бюджет душ: сначала то, что можно купить сейчас; не советовать уже купленное;
     учитывать, что предмет-апгрейд заменяет компонент.
  5. Уверенность: меньше порога матчей → «мало данных», опора на справочник.
- Каждый совет возвращает **причину простыми словами** («Против Seven: режет его spirit-урон»).
- Тесты в `tests/recommend.test.js` на 6+ сценариев (нет врагов, много хила у врагов,
  0 душ, всё уже куплено, новый герой без статистики, неизвестный id).
- **Готово, когда:** `npm test` зелёный, а на 3 ручных сценариях советы выглядят разумно для игрока.
- **Запрос:** «Сделай задачу 1.3. Сначала напиши тесты, потом функцию. Объясни мне формулу оценки простыми словами».

### [ ] 1.4 Главная страница
- `site/index.html` + `site/js/app.js` + `site/css/style.css`.
- Шаги на одном экране телефона: 1) мой герой (сетка иконок + поиск по имени),
  2) враги (до 6), 3) души (поле + кнопки +500/+1000), 4) купленные предметы (необязательно),
  5) кнопка «Что купить» → карточки 3 предметов с ценой, иконкой и причиной, ниже — контры.
- Тёмная тема, крупные кнопки, всё работает без перезагрузки страницы.
- Выбор запоминается в браузере (localStorage, обёрнут в try/catch).
- **Готово, когда:** на телефоне от открытия до совета — меньше 15 секунд и 10 тапов.
- **Запрос:** «Сделай задачу 1.4. Сначала покажи мне простой макет словами, потом код».

### [ ] 1.5 Страница героя
- Полный путь билда (ранние / основные / поздние / ситуативные), порядок прокачки, топ контр-предметов
  против этого героя, дата данных.
- **Готово, когда:** с главной можно перейти на страницу любого героя и обратно.
- **Запрос:** «Сделай задачу 1.5».

### [ ] 1.6 Сборка сайта
- `scripts/build-site.js`: копирует в `site/data/` только то, что нужно сайту (сжатый JSON),
  проверяет, что данные не пустые и не старше 3 дней, иначе падает с понятной ошибкой.
- `npm run dev` — простой локальный сервер для просмотра `site/`.
- **Готово, когда:** `npm run build:site && npm run dev` — сайт работает локально на свежих данных.
- **Запрос:** «Сделай задачу 1.6».

### [ ] 1.7 Автообновление через GitHub Actions
- `.github/workflows/update-data.yml`: раз в сутки (и кнопкой вручную) запускает
  fetch:static → fetch:stats → test → build:site и публикует `site/` на GitHub Pages.
- Если что-то упало — сайт остаётся на старых данных, мне приходит письмо от GitHub.
- API-ключ (если получен) — в GitHub Secrets.
- **Готово, когда:** ручной запуск workflow обновляет дату данных на сайте.
- **Запрос:** «Сделай задачу 1.7 и объясни по шагам, что нажать в настройках GitHub».

### [ ] 1.8 PWA и счётчик
- `manifest.json`, иконки, service worker (кэширует оболочку сайта; данные — «сначала сеть»).
- Яндекс Метрика: просмотры + цели «выбран герой», «нажал Что купить».
- Подвал: «Не связан с Valve. Данные: deadlock-api.com», дата обновления данных.
- **Готово, когда:** сайт ставится на телефон иконкой; в Метрике видны цели.
- **Запрос:** «Сделай задачу 1.8».

### [ ] 1.9 Тест на живых людях
- Дать ссылку 10–20 игрокам, собрать: что непонятно, где совет показался странным.
- Записать находки в `docs/feedback.md`, исправить топ-5.
- **Готово, когда:** минимум 10 отзывов собраны и разобраны.

## Этап 3. Свой сервер и Telegram-бот (1–2 месяца, ~$5–20 в месяц)

Цель: точная логика «равные с равными», единый API для сайта и бота.
Начинать, когда есть стабильный трафик (ориентир: несколько сотен посетителей в день).

### [ ] 3.1 Сервер
- Арендовать VPS (Ubuntu), настроить вход по SSH-ключу, firewall, автообновления.
- **Запрос:** «Объясни по шагам, как безопасно настроить VPS для Node.js, я делаю это впервые».

### [ ] 3.2 База матчей
- Загружать матчи текущего патча из дампов Deadlock API (deadlock-api.com/data-dumps)
  в базу (PostgreSQL или DuckDB — решить в задаче, записать в decisions.md).
- Хранить: герой, ранг, состав команд, покупки с временем, результат.

### [ ] 3.3 Пересчёт «равные с равными»
- Ночная задача: для каждого героя/ранга/отрезка времени — винрейт покупателей предмета
  против не купивших в той же точке игры.
- Перенос слоя 2 из этапа 1 на эти данные.

### [ ] 3.4 Бэктест
- Скрипт: на прошлых матчах сравнить, выигрывали ли чаще те, кто купил «как советуем».
- Результат — в `docs/backtest.md`. Цифру потом можно использовать в продвижении (только честную).

### [ ] 3.5 API советов
- Node.js (Fastify): `POST /recommend` (та же функция из `src/logic/`), `GET /heroes`, `GET /health`.
- Кэш ответов, ограничение частоты запросов, логи ошибок.
- Сайт ходит в API, а если API недоступен — работает на статических JSON (как на этапе 1).

### [ ] 3.6 Telegram-бот
- Библиотека grammY. Команды: `/start`, `/build <герой>`, выбор героя и врагов кнопками,
  ответ — 3 предмета с причинами + ссылка на сайт.
- Автопост в канал при новом патче (из задачи 2.5).

## Этап 4. Аккаунты и подписка (после первых тысяч пользователей)

### [ ] 4.1 Выбрать способ оплаты
- Сравнить варианты, доступные из Беларуси: белорусский эквайринг для ИП, Boosty, Telegram Stars в боте.
  Stripe и AdSense из Беларуси недоступны. Решение — в `docs/decisions.md`.
- Уточнить у бухгалтера налоги и нужно ли ИП.

### [ ] 4.2 Вход через Steam
- Steam OpenID: пользователь входит, мы знаем его Steam ID.

### [ ] 4.3 Платные функции
- Личный разбор: на каких предметах **ты** выигрываешь чаще, твои частые ошибки в покупках.
- Автоподстановка героев текущего матча (если API позволяет найти активный матч по игроку).
- Сайт и бот без рекламы.

### [ ] 4.4 Подключить оплату
- Оплата → флаг подписки у пользователя → платные функции открываются; отмена и возврат работают.
- Страницы: условия, политика конфиденциальности, контакты.
